# 从零到 Agent 开发面试：10 周学习流程

> 前提：你会前端（JS/TS），Python 接近零基础，每天 2 小时，周末 4 小时。
> 目标岗位：**AI 应用 / Agent 开发工程师（1–3 年）**，不是算法岗。
>
> 这份流程有两个约束：
> 1. **每周都有可验收的产物**，不是"看完了"。
> 2. **每个知识点都配追问**，因为面试考的是"被追问三层还站得住"。

---

## 0. 先搞清楚：这个岗位到底考什么

从 BOSS 直聘 1–3 年 AI Agent 岗的招聘要求归纳，考五块：

| 块 | 占比 | 考什么 |
|---|---|---|
| **工程能力** | 40% | Python、API、数据库、异步、部署、测试 |
| **Agent 核心** | 25% | ReAct、工具调用、记忆、多 Agent、终止条件 |
| **RAG** | 15% | 切分、召回、重排、评测 |
| **LLM 基础** | 10% | token、上下文、温度、embedding、幻觉 |
| **项目与表达** | 10% | 能不能讲清"为什么" |

**注意**：算法（LeetCode）在大厂会考，中小厂 1–3 年岗通常只考简单题。
不要一上来刷题，先有项目。

## 第 0 周（3 天）：环境与"能跑起来"

### 目标

不看教程，能把这个仓库跑起来，并改一行代码让测试变绿。

### 做什么

| 天 | 任务 |
|---|---|
| D1 | 装 Python 3.12、uv；`uv sync`；`uv run pytest -q` 看到 251 passed |
| D2 | 读 `pdc/models.py`（80 行）；改一个字段的注释，跑测试 |
| D3 | 读 `tests/test_parser.py`；照着写一条新测试（比如"空文件报错"） |

### 必须搞懂

- `uv` 是什么（Python 的包管理器 + 虚拟环境）
- `pytest` 怎么发现测试（文件名 `test_*.py`、函数 `test_*`）
- 为什么仓库里既有 `pyproject.toml` 又有 `uv.lock`

### 追问

**Q：为什么要 lock 文件？**
> 保证每个人、每次 CI 装到的依赖版本完全一样。没有 lock，`>=` 会在不同时间解析出不同版本，"我本地能跑"就出现了。

## 第 1 周：Python 核心（只学用得到的 20%）

### 目标

能读懂 `pdc/` 里 80% 的代码，能自己写 50 行脚本。

### 学什么（按顺序）

| 概念 | 对应仓库文件 | 学到什么程度 |
|---|---|---|
| `dataclass(frozen=True)` | `models.py` | 知道为什么不可变 |
| 类型注解 `str \| None` | 全仓库 | 能读，不要求写得很全 |
| `Protocol` | `llm.py`、`embed.py` | 知道它和 ABC 的区别 |
| 推导式 / 生成器 | `checks.py` | 能读懂 |
| 异常与自定义异常 | `parser.py` | 知道什么时候该抛 |
| `pathlib` | `paths.py` | 替代 `os.path` |
| `json` / `yaml` | `parser.py` | 能读写 |
| 上下文管理器 `with` | `jobs.py` | 知道资源释放 |
| `threading.Lock` | `audit_log.py` | 知道为什么需要 |

### 练习

写一个 `scripts/count_jobs.py`：读一个目录下所有 YAML，输出每个文件的 job 数、列数。
要求：有类型注解、有 `main()`、有一个测试。

### 追问

**Q：为什么 `PipelineFacts` 是 frozen dataclass？**
> 它会被多个工具共享。如果某个工具能改它，后面所有结论都不可信。不可变让"事实"这个词成立。

**Q：`Protocol` 和抽象基类有什么区别？**
> Protocol 是结构化类型：只要方法签名对，不需要继承。换模型/换 embedder 时不用改继承树。

**Q：Python 的 GIL 对 Agent 有什么影响？**
> CPU 密集型多线程并不能真并行；但 Agent 的时间花在等网络（IO），线程仍然有效。真要并行计算用多进程。

## 第 2 周：Web、数据库、异步

### 目标

能写一个带鉴权、异步任务、SQLite 持久化的 API。

### 学什么

| 主题 | 对应文件 | 关键问题 |
|---|---|---|
| HTTP 语义 | `api.py` | 200/202/401/403/404/429 分别什么时候用 |
| FastAPI 依赖注入 | `auth.py` | `Depends` 到底做了什么 |
| pydantic 校验 | `api.py` | 请求体校验在哪一层 |
| SQLite | `jobs.py` | 为什么用 WAL、什么是事务 |
| 异步 | `api.py` | `async def` vs `to_thread` |
| SSE | `api.py` | 为什么不用 WebSocket |

### 练习

给 API 加 `GET /stats`：返回任务总数、成功率、平均步数。
要求：走 SQL 聚合，不读全表；有测试。

### 追问

**Q：202 和 200 的区别？**
> 200 表示"请求已完成，结果在响应里"；202 表示"已接受，结果稍后取"。Agent 任务几十秒，同步等待会超时。

**Q：`async def` 里调用阻塞函数会怎样？**
> 卡住整个事件循环，所有请求一起卡。阻塞调用要么换 async 客户端，要么 `to_thread`。

**Q：SQLite 能用于生产吗？**
> 单机、低并发可以，而且零运维。多实例/高并发要换 Postgres。关键是说清边界，不是一味说"能"或"不能"。

**Q：为什么任务表要有 `mark_orphans`？**
> 进程重启后，内存里跑的任务没了，但数据库还写着 running。用户会看到永远转圈。启动时把这类标成 failed。

## 第 3 周：LLM 基础（不训练，但要懂）

### 目标

能解释模型的行为边界，不把"模型"当成魔法。

### 学什么

| 概念 | 必须能回答 |
|---|---|
| token | 中文/英文大概几个字符一个 token；为什么按 token 计费 |
| 上下文窗口 | 超了会怎样；为什么长文档要检索而不是全塞 |
| temperature / top-p | 0 为什么不一定更稳 |
| embedding | 是什么；余弦相似度为什么常用 |
| function calling | 模型真的执行代码了吗 |
| 幻觉 | 成因（训练目标、上下文缺失、指令冲突） |
| 推理模型 | 什么时候值得用（多步推理、代码），什么时候浪费 |

### 练习

跑 `lesson1/mini_agent.py`（40 行 ReAct），改成"先查天气再决定穿什么"。
观察：模型输出了什么、你的代码执行了什么。

### 追问

**Q：模型真的执行了工具吗？**
> 没有。模型只输出一个 JSON（工具名 + 参数），执行发生在你的进程里。理解这一点，才知道权限和沙箱该放在哪。

**Q：temperature=0 就稳定了吗？**
> 不一定。服务端仍有批处理差异、模型版本会变、上下文顺序会影响结果。要稳定，靠校验器和确定性代码，不靠温度。

**Q：为什么 embedding 能把语义变成距离？**
> 模型在大量文本上学会了"经常一起出现的词，向量也接近"。它是统计结果，不是理解。所以专有名词、否定句、数字它经常处理不好。

## 第 4 周：Agent 核心

### 目标

能不看代码手写一个 ReAct 循环，并说清每个终止条件。

### 学什么

- ReAct：Thought → Action → Observation 的循环
- 工具 schema：名字、描述、参数 JSON Schema
- 循环控制：max_steps、token 预算、取消、卡住检测
- Agent vs Workflow 的判据

### 读代码

`pdc/agent.py`（重点 `run_agent`）、`pdc/tools.py`、`pdc/yamlgen.py`（门禁）。

### 练习

给 `tools.py` 加一个 `count_columns` 工具，并在 agent 里用上；写测试。

### 追问

**Q：怎么判断一个任务该用 Agent 还是 Workflow？**
> 看"下一步做什么"是否需要判断。流程确定（哪怕分支多）就是 Workflow；需要根据中间结果决定查什么、要不要继续，才是 Agent。

**Q：Agent 的终止条件有哪些？**
> 四个：模型不再调工具、校验通过、步数上限、预算上限。生产里后三个必须有，否则会烧钱。

**Q：工具描述怎么写才准？**
> 写"什么时候用、什么时候不用、参数含义、返回什么"，不写实现细节。描述是给模型看的接口文档。

**Q：工具调用失败怎么处理？**
> 把错误类型和可执行的修复建议返回给模型，而不是抛异常终止。错误信息要包含字段名和位置。

## 第 5 周：RAG

### 目标

能解释"为什么召回不准"，并能用指标证明改动有没有效。

### 学什么

- 切分：按语义边界，不按行数；chunk 要自包含
- 召回：BM25 vs 向量 vs 混合；RRF / 线性加权
- 重排：解决"召回宽、排序乱"
- 评测：R@k、MRR、留一法、负样本

### 读代码/文档

`pdc/rag.py`、`pdc/rerank.py`、`docs/retrieval-design.md`、`rag/eval_sample.py`。

### 练习

跑 `uv run python -m rag.eval_sample`，把 α 从 0.1 改到 0.5，观察 R@5 变化。
写一句话结论：为什么 α 不能跨语料照搬。

### 追问

**Q：为什么混合检索？**
> 词法擅长专有名词和精确匹配，向量擅长同义表达。两路互补，不是谁替代谁。

**Q：重排为什么能提高 R@1 但不提高 R@5？**
> 重排只调整候选池内部的顺序，不引入新候选。所以"有没有进前 5"不变，"排第几"变了。

**Q：怎么防止评测自欺？**
> 留一法（候选集不能有答案）、`exact_match_rate`（必须为 0）、负样本（该空的时候要空）、报方差而不是最好成绩。

## 第 6 周：评测与幻觉治理

### 目标

能设计一套"改坏了会掉分"的评测，而不是全 1.0 的摆设。

### 学什么

- 四类幻觉：编造、遗漏、失真、越权
- 四层检测：结构、契约、语义、归因
- 硬门禁：finish 重新校验
- 评测指标：通过率、轮数、token、逐键差异
- 注入对照（sabotage）：证明检测器会响

### 读代码/文档

`pdc/spec_validator.py`、`pdc/spec_grounding.py`、`pdc/yamlgen.py`、`docs/hallucination-and-testing.md`。

### 练习

往一份合法 YAML 里删掉一列，跑 `pdc build`，看它被哪条规则拦住；
再删掉 `mapColumns`，看是否被拦住（这是曾经漏掉的一类）。

### 追问

**Q：为什么遗漏比编造危险？**
> 编造会报错，遗漏不会。少一列数据流水线照跑，三个月后对账才发现。

**Q：校验器太严会怎样？**
> 逼模型编造。输入文档本身有 7 列漂移时，要求"比输入更正确"只有两条路：永远失败，或偷偷加一列。

**Q：指标全 1.0 说明什么？**
> 说明测试没有区分度。要有注入对照，证明它会掉分；还要有负样本，证明它会拒绝。

## 第 7 周：工程化与部署

### 目标

能把服务跑起来、能解释一次请求的完整路径。

### 学什么

- FastAPI 中间件、依赖注入、后台任务
- SSE vs WebSocket
- Docker 多阶段构建
- CI：lint、test、镜像冒烟、备份演练
- 配置校验与 fail fast

### 读代码

`pdc/api.py`、`pdc/jobs.py`、`Dockerfile`、`.github/workflows/ci.yml`、`docs/api-and-ui.md`。

### 练习

本地起服务，用 curl 走一遍：提交 → 轮询 → 下载；再故意不带 token 看 401。

### 追问

**Q：为什么 Dockerfile 要两阶段？**
> 先装依赖（利用缓存），再拷源码装项目。依赖没变时，改代码不会重装依赖。

**Q：镜像能构建就等于能跑吗？**
> 不等于。CI 里加了冒烟：起容器、请求 `/health`、失败打印日志。构建成功但启动崩溃很常见。

## 第 8 周：企业级能力

### 目标

能回答"这是谁操作的、服务怎么样、数据丢了怎么办"。

### 学什么

RBAC、审计哈希链、指标/告警、备份恢复、配置校验。
读 `docs/enterprise-readiness.md` + 五个模块。

### 练习

跑一遍 5 分钟演示；手动改一条审计记录，看 `verify` 报第几条坏了。

### 追问

**Q：401 和 403 的区别？**
> 401 是没认证（不知道你是谁），403 是认证了但权限不够。混用会让排查方向错。

**Q：审计为什么要哈希链？**
> 普通表谁都能改。每条记录带上一条的哈希，改任何一条后面全对不上——最便宜的防篡改。

**Q：备份为什么要演练？**
> 没恢复过的备份等于没有。CI 里真的走创建→校验→恢复，才能证明它可用。

## 附 A：基础知识的 30 个追问（必须能答）

| # | 问题 | 一句话答案 |
|---|---|---|
| 1 | 进程和线程的区别 | 进程有独立内存，线程共享；Python 有 GIL，CPU 密集用多进程 |
| 2 | 协程是什么 | 用户态调度的轻量任务，await 时让出控制权 |
| 3 | `async def` 里能直接调阻塞函数吗 | 不能，会卡事件循环；用 `to_thread` |
| 4 | HTTP 幂等 | 同样的请求执行多次，结果一样；GET/PUT/DELETE 幂等，POST 不 |
| 5 | 401 vs 403 | 没认证 vs 权限不够 |
| 6 | 202 的语义 | 已接受，结果稍后取 |
| 7 | REST 和 RPC 的区别 | 资源 vs 动作；REST 用 HTTP 语义，RPC 用方法名 |
| 8 | 数据库索引为什么快 | B+ 树把随机 IO 变成有序查找；代价是写入变慢、占空间 |
| 9 | 事务的 ACID | 原子、一致、隔离、持久 |
| 10 | SQLite WAL | 写前日志，读写不互相阻塞；代价是多两个文件 |
| 11 | 什么是 N+1 查询 | 循环里查库；用 join 或批量查 |
| 12 | 缓存穿透/击穿/雪崩 | 查不存在/热点过期/大量同时过期 |
| 13 | 消息队列的作用 | 解耦、削峰、异步 |
| 14 | 幂等键 | 用唯一 ID 防重复提交 |
| 15 | token 是什么 | 模型处理文本的最小单位，按它计费 |
| 16 | 上下文窗口 | 一次能看的 token 上限，超了截断或报错 |
| 17 | temperature | 采样随机性；0 也不保证完全确定 |
| 18 | embedding | 把文本映射成向量，语义近的向量近 |
| 19 | 余弦相似度 | 两个向量夹角的余弦，只看方向不看长度 |
| 20 | 向量索引 HNSW | 分层近邻图，用少量精度换速度 |
| 21 | RAG 和微调怎么选 | 知识频繁变→RAG；风格/格式→微调 |
| 22 | 幻觉的成因 | 训练目标是"像人话"，不是"真"；上下文缺失也会导致 |
| 23 | function calling 本质 | 模型输出 JSON，你的代码执行 |
| 24 | ReAct 的核心 | 推理和行动交替，observation 提供外部事实 |
| 25 | 为什么需要 max_steps | 防死循环和烧钱 |
| 26 | 多 Agent 的主要收益 | 上下文隔离，不是"更聪明" |
| 27 | SSE 和 WebSocket | 单向推送 vs 双向；SSE 走 HTTP，自动重连 |
| 28 | Docker 镜像分层 | 每层缓存；依赖层放前面，代码层放后面 |
| 29 | 蓝绿/灰度 | 两套环境切换 vs 按比例放量 |
| 30 | 可观测性三件套 | 日志、指标、链路追踪 |
